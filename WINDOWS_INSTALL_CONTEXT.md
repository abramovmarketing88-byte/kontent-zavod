# Контекст по установке Windows и текущей проблеме

## Что произошло

При установке Windows появилась ошибка:

> Установка Windows на данный диск невозможна. Выбранный диск имеет стиль разделов GPT.

Это означает:

- внутренний диск компьютера размечен как **GPT**
- установочная флешка была запущена в режиме **Legacy / CSM**
- при такой комбинации установщик Windows не хочет ставиться на GPT-диск

## Что уже выяснили по BIOS

Материнская плата использует **Aptio Setup Utility (AMI)**.

Были замечены такие устройства:

- внутренний SSD: `KINGSTON SA400S37120`
- внутренний накопитель: `Firebat FEQC34B-512G`
- флешка отображалась как: `VendorCoProductCode 2.00`

Важно:

- `VendorCoProductCode 2.00` — это и есть установочная флешка
- когда **CSM / Legacy** был включен, флешка была видна в `Boot Override`
- после отключения **CSM** флешка пропала из списка загрузки

## Вывод по причине проблемы

Это почти наверняка означает, что флешка записана **не в UEFI-формате**, а в старом режиме **BIOS/Legacy/MBR**.

Из-за этого получаем такую картину:

1. **CSM включен**  
   Флешка видна и запускается, но Windows Installer стартует в Legacy-режиме и выдает ошибку про GPT.

2. **CSM выключен**  
   BIOS ищет только UEFI-загрузчик, а флешка его не содержит в нужном виде, поэтому она вообще не появляется как загрузочная.

## Какие настройки BIOS были найдены

В разделе `Advanced -> Compatibility Support Module Configuration`:

- `CSM Support = Enabled`
- `Boot option filter = UEFI and Legacy`
- `Storage = UEFI`
- `Video = Legacy`
- `Other PCI devices = UEFI`

Рекомендация:

- либо `CSM Support = Disabled`
- либо, если полное отключение недоступно, максимально перевести загрузку в **UEFI only**

Цель:

- запуск установочной флешки именно в **UEFI**, а не в Legacy

## Какие настройки не являются причиной проблемы

Не нужно менять это ради установки:

- `Lock Legacy Resources`
- `EHCI Hand-off`
- `XHCI Hand-off`
- `ACPI` настройки

Эти пункты не решают конфликт GPT/Legacy.

## Что нужно сделать правильно

Нужно **перезаписать установочную флешку под UEFI/GPT**.

### Вариант через Rufus

Если есть другой компьютер с Windows:

1. Скачать **Rufus**
2. Подключить флешку
3. Выбрать ISO-образ Windows
4. Выставить параметры:
   - **Partition scheme / Схема раздела:** `GPT`
   - **Target system / Целевая система:** `UEFI (non CSM)`
   - **File system / Файловая система:** `FAT32`
5. Нажать **Start / Старт**
6. Дождаться окончания записи

### После записи флешки

На целевом компьютере:

1. Зайти в BIOS
2. Отключить `CSM Support`  
   или перевести загрузку в `UEFI only`
3. Перейти в `Save & Exit`
4. В `Boot Override` выбрать флешку
5. Запустить установку Windows

После этого ошибка про GPT должна исчезнуть.

## Что НЕ нужно делать без необходимости

Не нужно сразу:

- конвертировать внутренний диск в `MBR`
- удалять все разделы
- чистить диск через `diskpart`

Это было бы нужно только если специально ставить Windows в старом Legacy-режиме, что здесь не является правильным решением.

## Краткое итоговое заключение

Проблема не в том, что BIOS "не видит флешку" вообще.  
Проблема в том, что текущая флешка записана для **Legacy/BIOS**, а ставить Windows нужно в **UEFI** на диск **GPT**.

### Одной фразой

Нужно **создать новую установочную флешку Windows в режиме UEFI/GPT**, затем загрузиться с нее при **отключенном CSM**.
